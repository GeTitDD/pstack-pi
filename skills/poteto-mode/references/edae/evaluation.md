# Evaluation first

实现前固定验收标准。优先使用仓库已有测试和评估工具，不为一次任务引入新的评估平台。

- 每个用例保存 case_id、输入、数据或 fixture 版本、预期行为或不变量、判定器和风险标签。
- 覆盖正常输入、边界、信息不足、应当拒绝、工具失败中与变更相关的情况。故障修复至少保留一个先失败后通过的复现。
- 确定性行为用断言。回答质量先定义可核验的事实与来源，再考虑人工或模型判定。模型不能独自判定权限隔离或副作用是否安全。
- 冻结模型、提示词、工具 schema、采样配置和数据版本。记录无法固定的依赖。
- 质量阈值、禁止回归项、成本和时延预算在候选运行前写明。仓库无预算时说明任务采用的限额与依据。
- 随机行为按预先确定的重复次数运行，报告样本量、成功数和失败分布。单次成功不能证明稳定性。无预算运行足够样本时标为证据不足。
- 同一用例集比较变更前后结果，保留失败项，不能只给平均分。区分开发集和留出集，避免对案例答案硬编码。

单独比较提示词、Skill 或模型效果时，回到 [Eval](../../playbooks/eval.md)，由它负责盲评和候选隔离。本文件负责工程验收，不复制实验调度协议。

可使用下面的最小记录，按仓库格式保存，不要求新 schema。

```yaml
case_id: retry-after-timeout
input: 同一作业超时后重试
fixture_version: fixture-local-v1
expected: 同一幂等键只有一次持久化结果
judge: 持久化记录数等于 1，状态为 succeeded
risk: H
baseline: artifacts/before.txt
result: artifacts/after.txt
```
