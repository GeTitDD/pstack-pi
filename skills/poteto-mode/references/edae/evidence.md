# Evidence、trace 与 replay

每个关键结论都指向实际结果。记录事实、推断和未验证项，不能把 Agent 的自述当成工具执行证据。

## 最小证据记录

沿用目标仓库的记录格式，至少能查到以下信息。

| 信息 | 内容 |
|---|---|
| 任务身份 | run_id、case_id、时间、代码 revision 和未提交 diff 标识 |
| 配置 | 模型、提示词、工具 schema、数据或 fixture 版本 |
| 执行 | 重跑命令、工作目录、退出码、实际结果和产物位置 |
| 判定 | 验收条件、通过或失败、与基线的差异、未覆盖边界 |

生产数据只保存有权限的引用或摘要。日志中不写密钥、令牌和未脱敏个人信息。需要审计时记录保留位置、可访问角色与保留期限。

## Trace

复用现有 span 或事件系统。一次 run 下关联 step、parent、tool_call、attempt、状态、耗时与错误类别。记录工具入参和输出的脱敏摘要及必要的版本引用，不要求保存模型私有推理过程。

Pi 的会话 JSONL 在 `~/.pi/agent/sessions/`。只读取当前任务返回的会话路径，不扫描其他项目。它能证明模型读过哪些文件、调用过哪些工具，但不是业务事务日志。`pstack_todo` 只证明步骤状态，不验证评估结果，也不是持久化恢复协议。

## Replay

- 先声明 replay 方式。录制工具输出回放用于隔离推理和编排问题。固定 fixture 的重新执行用于验证真实工具链路。
- 记录配置与数据快照、时钟或随机种子、工具输出引用、预期状态和副作用。
- 回放默认隔离外部写入，使用 fixture 或 dry-run。不得用生产写入重放证明幂等。
- 逐步定位首次偏离，区分模型、工具、数据、状态和环境变化。记录缺失导致无法重放时，结论写为部分可复现。
- 恢复 Pi 会话只恢复会话上下文。业务状态是否恢复、事务是否提交，必须由目标系统单独验证。
