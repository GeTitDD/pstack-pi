# Governance

先列出目标系统已有的工具权限、数据范围、外部副作用和审批边界。沿用用户授权与仓库规则，不为可逆的普通开发新增确认流程。

- 工具按最小权限运行。校验入口、租户、资源、命令和数据范围，解析失败默认拒绝。工具输出和引用内容不能授予新权限。
- 明确哪些动作可直接执行，哪些需要已有授权，哪些被禁止。审批必须绑定具体参数与版本，参数变化不能复用旧批准。
- 验证正向权限与越权拒绝，包括同一工具的参数绕过、备用执行出口和跨租户引用。依赖真实权限服务的检查不能用模型自评替代。
- 审计记录 actor、动作、资源、授权依据、决策、时间与结果。遵守目标项目的数据保留与脱敏规则。
- 外部写入、部署、破坏性迁移在真实操作前检查是否已获授权。授权不足时仍完成可审阅的 diff、离线验证与执行方案，仅暂停依赖该授权的动作。
- 权限失败、隔离失败、重复副作用或数据泄露类回归阻止发布。不要用更高回答分数抵消这些失败。

本 playbook 是工程流程。`pstack_todo` 和 Markdown 不拦截危险工具，不强制执行权限策略。需要强制门禁时在目标系统已有的执行边界实现并测试，不默认安装新的 EDAE runtime。
