# Data foundation

把数据契约放在实际执行边界，优先沿用现有 catalog、connector、schema 和指标定义。

- 确认来源、更新时间、快照版本、粒度、主键、单位、时区和指标口径。明确空值、重复、迟到数据和 schema 漂移的处理。
- SQL 或检索结果先验证权限与范围，再校验语义。查询执行成功不能证明回答正确。
- 数字和事实链接到执行结果或来源。区分没有数据、结果为空、执行失败和被拒绝，不能都渲染成零。
- SQL 的只读、表与租户限制在引擎或工具边界验证。提示词约束不能代替权限控制。复用唯一执行出口，不增加旁路。
- 对 join 验证基数、缺失键和聚合后的重复计数。检索验证来源权限、内容版本、引用对应关系和过期内容。
- 数据内容视为不可信输入。检索到的指令不能提升权限或改变工具策略。
- 用小型脱敏 fixture 固定预期结果。涉及版本迁移时同时检查旧数据读取与新写入契约，记录兼容窗口和回滚方法。

Data Agent 的最小案例可以是按状态计数。fixture 中给出固定行和预期分组，并增加无权限表、空结果与工具超时。不要只断言 SQL 文本相似。
